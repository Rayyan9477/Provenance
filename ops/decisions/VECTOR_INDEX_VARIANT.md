## The decision

Variant A is the first form in `specs/10_DATABASE_DDL.md` §5.1. It succeeded on the first attempt, so B and C were never tried:

```sql
CREATE VECTOR INDEX evidence_embedding_ann_idx
    ON evidence_items (user_id, embedding vector_cosine_ops);
```

| Question | Answer | Probe |
|---|---|---|
| `feature.vector_index.enabled` | Already `true` by default, **and** settable by the bootstrap user | P2 |
| `VECTOR(1024)` type | Accepted | P4 |
| Cosine `<=>` and `vector_cosine_ops` | Both available | P5, P6 |
| Variant A syntax | Accepted | P6 |
| Prefix column position | `k` at `seq_in_index = 1` | P7 |
| Two-column prefix | Accepted — optional index variant R available | P8 |
| Planner selects the index | Yes, at 1024 dims — `vector search` with `prefix spans` | planner proof |

## Consequences

**The cosine posture holds.** `EMBEDDING_NORMALIZATION=L2_UNIT` is **not** required and Variant C's L2-ordering equivalence argument is not invoked. Titan v2 is still requested with `"normalize": true` — measured L2 norm `1.0000000` — but that is now a free property rather than a correctness dependency.

**The brute-force fallback is not needed.** `PV_RETRIEVAL_MODE` stays `VECTOR_INDEX`. The vector-indexing claim is unblocked and requires no disclosure in Judge Mode. `G6.2` and release item `S5` tool 1 are unblocked.

**Optional index variant R is available but not adopted.** P8 proved a two-column prefix works. It stays unadopted until retrieval evaluation justifies it; the default over-fetch-then-filter path (`k_raw = greatest(40, 4 * k_final)`, `k_final = 20`) is unchanged.

## The constraint this decision carries

**The ANN query vector must reach the planner as a literal or a bound parameter.** Verbatim from the regenerated transcript:

```
RUN A -- query vector as a correlated SUBQUERY:
  table: _pv_probe@_pv_probe_pkey
  spans: FULL SCAN

RUN B -- identical query, query vector as a LITERAL:
  • vector search
      table: _pv_probe@_pv_probe_a
      prefix spans: [/'00000000-0000-4000-8000-000000000001' - /'00000000-0000-4000-8000-000000000001']
```

Correct results, no error, no warning — only latency, which is invisible at demo scale. Survives `ANALYZE`, so it is not a statistics artifact; reproduced at 3 and 1024 dimensions, so it is not dimension-dependent.

Phase 6 must therefore embed first and pass the vector as a bound parameter, never computing it inside the ranking statement. `G6.2` asserts the `EXPLAIN` names the index — but only catches this if the assertion runs against the production query shape, parameter binding included.

Tracked as `D-06-001`.
