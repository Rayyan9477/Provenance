WHY THIS EXISTS
---------------
This task was authored implementation-and-tests-in-one-pass rather than
literally RED first, and ops/tdd/GREEN_T13.1-13.5.txt says so. A RED transcript
for a CDK app would only show "the module does not exist", which proves nothing
about whether the assertions bite.

This is the stronger proof. For each row: break ONE asserted property in the
source, run the test that is supposed to catch it, confirm it FAILS, restore the
file byte-for-byte. A row where the test still passes is a vacuous assertion and
the harness reports it as MISSED.

Twenty rows. Twenty caught. Zero missed. Suite green before and after.

The harness lives in the session scratchpad, not in the repository: it mutates
source files, and a script that rewrites infra/cdk/ has no business being
committed next to it. It is reproduced in full at the end so the run is
repeatable.

================ What each row is actually protecting ================

S1   BEDROCK_REASONING_MODEL_ID -> us.anthropic.claude-opus-5
     Opus 5 is DENIED on this account. A policy or an environment default naming
     it would fail at the first invocation with an AccessDeniedException that
     reads like a permissions bug rather than a model-access one.
     Caught by test_no_denied_model_id_appears_anywhere, whose regex is anchored
     on both sides precisely so it does not false-alarm on the valid dated haiku
     id that contains a denied id as a prefix.

S2   BEDROCK_EMBEDDING_MODEL_ID -> us.amazon.titan-embed-text-v2:0
     The mirror-image rule: Anthropic chat models take ONLY the profile id and
     every other provider takes ONLY the bare id. A `us.` prefix on Titan is a
     ValidationException, not a nicety.
     Caught by test_the_embedding_contract_is_frozen.

S3   instance role S3 statement -> ["s3:GetObject","s3:PutObject",
     "s3:DeleteObject"] on "*"
     Evidence is append-only and tenant/user are the first two key segments.
     Caught twice: by the wildcard-resource sweep and by the named-absence test
     for s3:DeleteObject on the instance role.

S4   PassRole resource -> a literal twelve-digit account id
     The account id is a targeting primitive for a confused-deputy attack
     (40_INFRA_IAC.md section 757) and is the value most likely to be pasted in
     by hand.
     Caught by test_no_template_contains_a_literal_account_id.

S5   a DSN with a password added to RuntimeEnvironmentVariables
     This is G13.6's exact failure mode, caught at synth time instead of after
     deploy — which matters, because the literal would already be in cdk.out and
     in every CloudFormation event by the time the gate command ran.
     Caught by the G13.6 variable filter and by the credential-shape sweep.

S6   provenance-agent-runtime granted provenance.action/execute
     The graph that writes a dispute letter must be structurally incapable of
     sending it.
     Caught by test_the_agent_client_cannot_execute_actions_or_dispatch_the_outbox.

S7   the inbound bucket's SES grant loses aws:SourceAccount
     Without it, any AWS customer's receipt rule can write into the evidence
     store. That is evidence injection, not a noisy neighbour.
     Caught twice: by the bucket-specific test and by the generic
     service-principal-in-a-resource-policy sweep.

S8   iam:PassRole loses iam:PassedToService
     An unconditioned PassRole is a privilege-escalation primitive.
     Caught by the generic PassRole sweep and by the "only one PassRole in
     Compute" test.

S9   ses_ingest given COCKROACH_DATABASE_URL_SECRET_ARN
     "No worker holds a SQL credential" has exactly one documented exception,
     and a second one appearing must fail.
     Caught by test_only_the_cognito_trigger_receives_a_database_credential.

S10  action_execute given ses:SendEmail on *
     Invariant 4 in IAM. The executor's inability to reach SES is what makes the
     control plane's revalidation the only path to a send.
     Caught by the named-absence test and by the wildcard sweep.

S11  outbox sweep input -> passes:1, pass_gap_seconds:0
     Scheduler's minimum rate() is one minute; the 30-second guarantee is met by
     sweeping twice inside one invocation. Dropping the second pass halves the
     guarantee silently.
     Caught by test_the_outbox_sweep_fires_once_a_minute_and_sweeps_twice.

S12  an expiration added to the raw/ lifecycle rule
     A lifecycle rule that expires an artifact makes a State Proof unciteable
     four months later, and nothing fails loudly when it happens.
     Caught by test_only_normalized_output_expires.

S13  ECR tag mutability -> MUTABLE
     With mutable tags, sha-abc123 can point at different bytes than the reviewer

S14  the advocate rule's attention_level filter deleted

================ Not covered by this matrix ================

Stated so the coverage claim is bounded rather than implied:

  - Nothing here proves a deployed behaviour. Every row is a template-level
    property.
  - The advocate rule's real fragility (section 17.8: every routed detail-type
    must actually CARRY attention_level in its payload) cannot be tested from a
    template. It needs the spec_lint check and the PutEvents contract test named
    in 40_INFRA_IAC.md section 6.3, and neither is in this builder's scope.
  - IAM policy SEMANTICS are not simulated. The suite proves a policy names what
    it should and omits what it should not; it does not prove AWS evaluates it
    the way the comment claims. `iam simulate-principal-policy` after deploy is
    the thing that would.
