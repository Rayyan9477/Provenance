Sixteen new adversarial assertions (T8b), added on top of the forty-two already
in test_adversarial_isolation.py. They assert sweeping PROPERTIES rather than
enumerated doors: every read and every write the API issues is issued under the
calling principal's own scope, a valid cursor minted in another session is
honoured as a sort position and never as an authority, and a cross-scope 404 is
byte-identical to an absent 404 rather than merely sharing its error code.

WHY THIS RED IS A COUNTERFACTUAL AND NOT A "RUN BEFORE THE CODE EXISTED"
--------------------------------------------------------------------------------
These tests were written against a surface that already answers. Running them
before writing them is not available, and a RED capture that only shows an
ImportError would prove nothing about the assertions themselves. What is
available -- and what is recorded below -- is the stronger claim the sabotage
matrix asks for: each assertion FAILS when the property it names is removed.
Both sabotages were installed, run, and reverted; `git status` after the second
revert shows the tree unchanged.

Two sabotages, chosen to be the two real defect shapes:

  A. app/api/deps.py::owner_scope stops deriving the scope from the resolved
     principal and returns a constant (Rob's) scope instead. This is the
     "the query ran under the wrong user" defect -- severity B2.

  B. app/api/routes/memory.py::case_detail distinguishes "exists, but not
     yours" from "absent", answering 403 FORBIDDEN with the id in `details`
     for the former. This is the section 1.7 defect: a 403 confirms that
     another user's object exists. (The mechanism is stubbed rather than
     wired to a real unscoped lookup, because the fake read port has no
     unscoped lookup for a route to call by accident. The observable
     behaviour -- two different answers for two ids -- is the defect.)

The internal-surface assertions in this file (the binding a handler is handed)
are additionally covered by the G8.5 lane in tests/auth/test_capability_binding.py
and by the PV_SABOTAGE hook on api.auth.route_class_check.
