WHAT THIS TRANSCRIPT IS, AND WHAT IT IS NOT
-------------------------------------------
This is a BUILD-AGAINST-CONTRACT transcript. Phase 8's control plane does not
exist, so nothing in apps/web has ever spoken to a Provenance API. Every screen
was written against docs/specs/15_API_SPEC.md, and every payload it renders in
this state comes from src/fixtures/hero.fixture.ts through a single declared
adapter, with a non-dismissible banner on every screen saying so.

Consequently: no G12.x exit assertion that requires a running API or a browser
has been run, and none is claimed. See the closing section for which are
passable now and which are blocked on Phase 8.

This task did NOT follow a literal RED-first sequence for the screens, and
saying otherwise would be dishonest. A RED transcript for a page component is
"the route 404s", which proves nothing about whether the honesty rule bites. The
equivalent proof is mechanical and is the centrepiece of this transcript: a
six-rule checker that runs in `npm run build`, a counterfactual mode that plants
one deliberate violation per rule and fails if any rule does not fire, and one
live sabotage of a real component recorded below.

THE RULE
--------
Nothing renders that has no backing row. No hard-coded id, no fixture
masquerading as live data, no placeholder that looks like a value. Where data is
unavailable the UI says so; it does not invent a plausible number.

The R6 plant is the one worth reading. It is an outstanding balance that falls
back to zero when the amount is missing. It reads as careful defensive code, it
never throws, and it renders a number indistinguishable from a real balance of
zero — which on this product's hero case is itself a true and load-bearing
value, because a disputed balance changes `status` and never `amount`. A reader
cannot tell the two apart, and neither can a reviewer.

DEFECT FOUND AND FIXED (pre-existing, in code written before this session)
-------------------------------------------------------------------------
src/components/proof/Grounding.tsx discriminated a grounding edge's source with
`"evidence_id" in source`. ClaimSource also declares `evidence_id` (nullable,
naming the evidence a claim was extracted from), so the predicate was true for
both and every counterparty claim would have rendered in the evidence treatment:
quoted as source text, with its authority score presented as an extraction
confidence. On the hero case that is the invoice claim rendered as admitted
evidence — the exact confusion the product exists to prevent. Corrected to
`"exact_text" in source`, which is on EvidenceSource alone, in all three places
the test appears.

FORMATTING DEFECT FOUND AND FIXED
---------------------------------
`Intl.DateTimeFormat("en-GB", { month: "short" })` renders September as "SEPT"
in current ICU, and every other month as three letters. The demo clock is
18 September 2026, so the one month where the locale disagrees with canon is the
only month the hero dataset shows. Uncorrected, every date in the recorded demo
would read "18 SEPT 2026" against a design and a CANONICAL_DECISIONS entry that
both say "18 SEP 2026". formatDate now assembles from formatToParts and
truncates the month to three letters. Locale is pinned to en-GB.
